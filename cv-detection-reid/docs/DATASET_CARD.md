# Dataset Card — cv-detection-reid

**Reference:** PRD §7 · **Version:** see `config fingerprint` + `dataset_hash` in any report

---

## What this dataset is

A **synthetic scene set with pixel-exact ground truth**, built to unblock the
project's critical path. The PRD is explicit that annotation is the true
bottleneck (§15.2, Risk R1), and until labels exist nothing downstream —
splitter, metrics harness, tracker, ReID gallery — can be exercised or tested
at all.

| Property | Value |
|---|---|
| Scenes | 18 videos across 16 scenes (two scenes have two camera views) |
| Source videos | 450 frames each @ 30 fps, 960×540 |
| Sampled frames | 540 (2 fps, per PRD §7.1) |
| Annotated boxes | 1,755 valid (376 further boxes marked `ignore`) |
| Classes present | `person` (1,002), `bus` (753) |
| Classes with **no** data | `car`, `truck`, `motorcycle`, `bicycle` |
| Splits | train 360 / val 90 / test 90 — **by scene**, leakage-tested |
| Ground-truth format | MOT-Challenge (`data/gt/*_gt.txt`) → YOLO labels |

## How it was made

**Object pixels are real.** Crops of people and a bus are cut out of two
photographs using the COCO-pretrained detector, then composited onto procedural
backgrounds along known trajectories. The detector is therefore looking at real
photographed objects and its scores mean something.

**Backgrounds are synthetic.** Absolute mAP here is **not comparable to a
road-scene benchmark** and is never presented as such.

**Ground truth is exact, including identity and occlusion.** Trajectories,
track ids and per-frame visibility fractions are known by construction — an
id-buffer records which pixels each object still owns after everything is
painted. That gives MOTA/IDF1/HOTA and the post-occlusion recovery rate a
ground truth no human annotator could produce.

## Controlled difficulty axes (PRD §13.3)

Each scene isolates one axis, so a slice measures the thing it is named after
rather than whatever the footage happened to contain.

| Axis | Scenes |
|---|---|
| Daylight, clear | 01, 04, 06, 07, 11, 14, 16 |
| Dusk | 02, 09, 12, 15 |
| Night (+ sensor noise) | 03, 10, 13 |
| Full occlusion (pole) | 04, 09, 11, 13, 14, 15, 16 |
| Camera motion (pan) | 05, 10, 12, 16 camB |
| Motion blur | 08, 12 |
| Crowded (> 8 objects) | 07, 11 |
| Two camera views | 06 (camA/camB), 16 (camA/camB) |

Occluders are deliberately spread across all three lighting conditions: the
splitter stratifies by lighting, so clustering every occlusion event in one
condition would leave a whole split with no way to measure M17.

## Splits

Assigned **by scene**, never by frame (PRD Principle 4; Risk R3 rated
*Critical*). Two camera views of one scene are the same scene and go to the
same split. Enforced by `tests/test_no_leakage.py`, which also verifies the
guard fires on a deliberately leaked manifest.

Scenes are dealt in a lighting-stratified round-robin so each split sees a mix
of conditions. Stratification is on an attribute recorded at sampling time,
never on model performance — choosing a test set by how well the model scores
on it is the same class of error as a leak, one stage later.

## Known limitations

1. **Only 2 of 6 classes have any data.** Per-class AP reports `no GT` for the
   other four rather than fabricating a number, and M6 is unverifiable for them.
2. **No small objects.** Every object exceeds 32² px, so **M7 reports `n/a`,
   not 0.0** — "no small objects here" and "missed every small object" are
   opposite findings.
3. **Rectangular composites.** Sprites are pasted as rectangles, so object
   edges are cleaner than in real footage. Localisation is slightly easier and
   occlusion boundaries slightly sharper than reality.
4. **Synthetic backgrounds** lack the clutter, shadows and confusable structures
   that generate real false positives, so precision here is optimistic.
5. **`weather` is unpopulated** — no rain scenes are generated, so that slice
   from PRD §13.3 is absent rather than empty.

## Licensing and provenance

Sprite source photographs are Ultralytics' public sample assets
(`bus.jpg`, `zidane.jpg`), used as a source of object pixels. Backgrounds and
trajectories are generated by `scripts/make_sample_videos.py` and carry no
third-party rights.

**No real people were surveilled to build this dataset**, which is also why it
is a reasonable artefact to commit and share for a surveillance-class project.

## Replacing it with real data

The pipeline does not know or care that this data is synthetic:

```bash
# 1. Drop real footage in.
cp /path/to/*.mp4 data/raw_videos/
#    Name files <scene>_<camera>.mp4 so two views of one scene stay together.

# 2. Annotate in CVAT/Roboflow, export MOT format to data/gt/<stem>_gt.txt.
#    Read docs/annotation_guide.md BEFORE labelling starts.

# 3. The same three commands.
python -m src.cli sample && python -m src.cli labels && python -m src.cli split
```
